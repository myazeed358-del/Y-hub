# Online lectures

API-v2 education application `/online-lectures`; independently discovered and excluded from engine catalogs. Focused child branch of attendance. Migration **0036** extends the SAME `academic_lectures` table with `delivery_mode` (`in_person` default, `online` for the guarded online scheduling RPC) and adds audited lecture participant blocks. Existing course/section identities and attendance links remain unchanged. In-person lectures cannot obtain media tokens.

The UI provides section scheduling, upcoming lectures, cancellation, joining, participant tiles, microphone/camera controls, screen sharing where supported, transient bounded chat, moderator removal, and explicit audio playback for mobile autoplay restrictions. Arabic/English and existing theme tokens are used. Camera/mic are disabled until the user chooses them; leaving unmounts/disconnects, including a connection that resolves late. No recording or archived chat is implemented or implied.

## Server authorization and media boundary

`supabase/functions/lecture-access` verifies the caller with native Supabase Auth, then calls `lecture_join_permission` with the SAME user JWT. Database checks current role, instructor assignment, enrollment, delivery mode, cancellation, explicit blocks and server-time joining window (15 minutes before start through scheduled end). Client-supplied identity, role, room or expiry cannot grant privileges. Row locks stabilize authorization during the database transaction. HMAC-SHA256 LiveKit tokens bind room and user, expire in30 seconds, omit roomAdmin and prohibit updating one's own metadata. Moderators receive UI controls, not browser provider-admin credentials. Gateway JWT verification should remain enabled; handler authorization is additional and never trusts gateway role claims alone.

`LectureProvider` isolates LiveKit SDK2.23.0. Server API key/secret and service-role credentials are only Edge Function environment variables. Never use VITE-prefixed secrets. The configured public media URL is wss://; server RoomService calls use HTTPS. CORS uses explicit configured app origins; responses are no-store. Browser code only gets a short-lived participant token, never provider or Supabase service secrets.

Removal first commits an audited database block through the user's authorized RPC, then requests SFU disconnection. A provider failure returns `disconnect_pending` rather than success; the block remains, new admissions are denied and scheduled reconciliation retries. The reconciler enumerates owned-prefix rooms and compares participants with CURRENT server permissions using a service-only RPC. It removes withdrawn, demoted, reassigned, blocked or out-of-window participants. No frontend timer is the security boundary. Secrets, tokens, chat and media are not audit payloads; removal reason is redacted. Required audit failure rolls back a block.

3. Deploy `lecture-access` with gateway verification retained. Configure an authenticated scheduler at most every30 seconds to POST `{"action":"reconcile"}` with the scheduler secret in `x-reconcile-secret` and the gateway-required server Authorization credential. Store these only in the scheduler's secret store. Validate gateway key compatibility in staging; do not disable authorization to get a green deployment.
4. Monitor non-200 reconciliation responses and retry. No mail service is introduced. Scale/shard the reconciler when room/participant count approaches Edge execution/time budgets; load-test with real participants before release.
5. Validate actual media joining, participant removal/reconnection, TURN, camera/mic permissions, screen-sharing availability, autoplay, mobile reconnect and scheduler outages on isolated staging/accounts. None is claimed as passed here.

Admission is checked at issuance; a previously issued token can remain usable for its remaining30-second TTL. Established media sessions require the server reconciler: JWT expiry itself does NOT disconnect them. Withdrawal/end/block removal has scheduler/provider latency, and provider/DB outages can delay disconnection. Do not advertise immediate revocation or production readiness until reconciliation is deployed and observed. Logout disconnects this UI; media credentials are a separate lease, not a guarantee of immediate global Auth-session revocation. Chat and media are relayed by the provider, not claimed end-to-end encrypted by this implementation.
