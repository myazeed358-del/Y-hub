## Findings fixed in the unmerged migration 0022

1. **Authorization after role revocation (high, inherited domain-policy defect).** Historical material/exam/question policies allowed the course owner to write regardless of current application role. A demoted instructor could still INSERT or UPDATE child content under those policies. The reproduction failed six subcases: three unauthorized updates succeeded and three unauthorized inserts succeeded. Migration 0022 now adds restrictive INSERT/UPDATE/DELETE policies for authenticated callers on those three tables, requiring `auth_can_manage_content()`. These compose with existing ownership policies, grant nothing, and leave SELECT/enrollment rules intact. They use the existing database-role helper and the audit transaction's actor lock; no frontend substitute or new privilege is introduced. Post-fix regression checks inserts, updates, deletes, unchanged rows and event counts; enrolled student material reads still pass. Existing successful instructor writes remain covered by the cascade/content tests.

2. **Unrecorded identity/time changes (audit-integrity gap).** A primary-key-only course update was authorized but skipped by the capture allowlist, leaving no event connecting its old and new IDs. A failing regression reproduced zero events under the new ID. Creation/enrollment timestamps were also outside the allowlists despite being writable domain fields. Trigger registration now tracks `id` on all eight tables and domain `created_at` / `enrolled_at` fields. Rename events identify the new entity ID and retain both IDs in before/after values; original events retain their original IDs. Profile timestamps/PII remain excluded. A schema-coverage test requires every column of the seven non-profile tables to have an explicit tracked classification, preventing future silent gaps.

3. **Unsafe free-text values in retained evidence (privacy gap).** `users.major` and `questions.difficulty` are unconstrained TEXT, not database enums. The old visible-value allowlist could retain arbitrary secret-like content supplied there. A creation/change regression reproduced a synthetic secret in audit JSON. Both values are now redacted, including old values, while changed-field names and the `access_changed` action remain available. Role is constrained by the event role contract; UUIDs, booleans, numeric metadata, constrained domain enums and timestamps remain visible. Actor display name is still an intentional personal-data snapshot required by the review UI, not a verified unique identity or a general-purpose secret scrubber.

4. **Failed deletes presented as successful UI progression (failure-handling defect).** Existing exam/question delete handlers ignored the Supabase error result, clearing selection/reloading after the database rejected a mutation (including mandatory audit-write failure). Two new negative-control tests reproduced that behavior. Handlers now show a generic existing-style error toast and return without success state changes; backend details are not exposed. Four additional cases retain successful deletion and cancellation behavior. This is a narrow fix to the audited write path, not a course-feature refactor.

Only this PR's not-yet-deployed 0022 migration is amended; historical migrations 0001–0021 are untouched. If someone applied an earlier 0022 to a separate staging instance, rebuild that disposable instance or prepare a separately reviewed forward migration; do not assume editing this file updates an already-migrated database.

## Reviewed trust boundaries and evidence

- **Identity:** `auth.uid()` supplies actor ID; database profile supplies role/name. Shared actor-row lock pins role through commit. Both orderings are tested: a role update waits for an existing mutation, and a mutation starting while demotion is pending cannot use the stale role once the demotion commits. An application JWT role label does not override database role. Trusted service operations without a user have null identity and `system`, never a fictitious user.
- **Privilege surface:** private schema/functions are inaccessible to browser roles; explicit grants expose SELECT only on audit stores. Immutable statement triggers reject UPDATE/DELETE/TRUNCATE. Audit read-role helper accepts no arbitrary identity. All relevant SECURITY DEFINER functions have empty search paths and qualified relations. Tests introduce temporary shadow objects and a forged role claim without gaining access. Write-forgery tests now require permission-denied errors, rather than accepting any failure such as a constraint violation.
- **RLS/RPC:** Admin can read only non-reserved instructor-origin records; Super Admin can read all; other application roles cannot read central evidence. Account/access records remain reserved. Current viewer role is database-derived; demotion removes subsequent query access. Search is SECURITY INVOKER with paired keyset cursors, bounded limit, date validation and the same RLS as direct queries. No new view or event insertion RPC exists. Notifications inherit visibility through the event relationship.
- **Atomicity:** required audit insert errors propagate into the parent transaction. A new cascade failure injection confirms parent, child, event and notification rollback together. No-op changes remain suppressed; multiple semantic actions remain one row event. Parallel edits preserve coherent before/after values.
- **Retention:** events have no actor/entity FK. A new account-delete regression confirms the earlier instructor snapshot survives, cascading deletion is marked as system maintenance, and Admin sees only the historical instructor event rather than the system event.
- **Notifications:** enqueue errors are caught only after required event insertion, with a SQLSTATE-only warning; an idempotent, service-only repair RPC reconstructs missing intents. Delivery is not implemented; this is a distinct durable intent ledger. Query cancellation/transaction abort cannot promise persistence, and rolled-back/denied attempts require a separate channel if needed.
- **Frontend/host:** reviewed page, dialog, domain DTO/filter parser, translations, repository, hook, public export, API-2 manifest and their tests. The page is read-only, bounded server pagination is used, errors avoid backend details, and React escapes values. Routing remains admin/Super Admin guarded without engine/dashboard registration changes. The audit UI needed no changes; two existing audited delete handlers now respect failed database results.
- **Related code:** checked the historical schema/permission chain, role/profile functions, course/dashboard repositories, content mutation handlers and Storage interaction, plus Docker test harness/bootstrap/fixtures. Review is limited to this feature and its authorization dependencies, not a certification of unrelated platform features.
