> نطاق العمل: إعادة تنظيم فعلية متعددة المناطق على **نسخة ZIP مستقلة** من `main` بتاريخ 14 أكتوبر 2026. لم يتم تغيير مستودع GitHub أو قاعدة البيانات الفعلية. هذه دفعة هندسية واسعة، **وليست شهادة باكتمال فصل كل ملفات المشروع أو جاهزيته للنشر**.

## ما نُفّذ في الملفات

### المساقات والتخزين

- انتقلت نماذج المساقات والخطط والإشارات المرجعية إلى `src/features/course-manager/domain/courseModels.ts`.
- انتقل التنفيذ الفعلي لـ IndexedDB إلى `src/features/course-manager/storage/indexedDbCourseStore.ts`، **دون تغيير اسم قاعدة البيانات أو إصدارها**؛ لحماية البيانات المحلية الموجودة.
- انتقلت مزامنة السحابة القديمة إلى `src/features/course-manager/services/legacyCloudSync.ts`. **لم تُعدَّل استعلاماتها**؛ لا تزال بحاجة مراجعة توافق مع مخطط Supabase وصلاحيات RLS قبل استخدامها.
- أصبحت `src/utils/courseStorage.ts` و`src/utils/cloudStorage.ts` واجهتي توافق فقط.
- انفصل توليد الجدول الزمني الدراسي إلى `src/features/course-manager/domain/generateTimeline.ts`.

### المحتوى التعليمي والواجهات

- انتقل توليد شرح الدروس التجريبي إلى `src/features/ai-generator/lesson-plan/generateLessonPlan.ts`، دون تحويله إلى خدمة ذكاء اصطناعي حقيقية؛ وظيفته لا تزال **محاكاة**.
- أصبح `src/utils/pdfEngine.ts` واجهة توافق، مع الإبقاء على كل عمليات التصدير السابقة.
- انتقلت طباعة تقارير الحل إلى `src/features/solver/services/printSolverReport.ts`، وأصبح مستهلكها المباشر ضمن ميزة Solver؛ `src/utils/pdfExport.ts` واجهة توافق.
- انتقلت واجهة 404 القابلة لإعادة الاستخدام إلى `src/shared/ui/NotFoundScreen.tsx`، وأصبحت صفحة `not-found` تصدّرها، وتستخدمها `legacy-lesson` دون الاعتماد المباشر على Feature أخرى.

### محركات الرياضيات وPython

- انفصل `SystemODEOrchestrator` إلى `src/services/math/ode/system_orchestrator.ts`؛ المسار السابق ما زال يعيد تصدير الصنف بلا تغيير اسم API.
- أضيف ناقل مشترك لبروتوكول Python المرحلي: `src/services/math/python/phaseClient.ts`، ويوفر مهلة انتهاء وتنظيفًا مضمونًا للـ timer والتحقق من شكل الاستجابة.
- انتقل تحليل بيانات الجبر الخطي وتحويلها إلى `linearAlgebraMapping.ts`. يمنع المحوّل إرسال خلايا رمزية كأصفار، ويحافظ على الكسور الدقيقة، ويرفض نتيجة `solved` التي تفتقر إلى نتيجة رياضية فعلية. المدعوم حاليًا في مسار Python المتحقق منه: `rref`, `inverse`, `determinant` و`svd` بالوضع العددي؛ العمليات الأخرى ترجع إلى TypeScript.
- انتقل تحويل RHS القادم من Python إلى نتائج ODE إلى `odeResponseMapping.ts`، ويُرسل محوّل ODE المتغيرات بشكل AST بدل سلاسل نصية، ويمتنع عن اعتبار مصفوفات حلول ناقصة نتائج صالحة.
- حدثت محوّلات Calculus وFuzzy وODE وLinear Algebra لاستخدام ناقل موحّد. **خدمة Python الأخرى (`python_math_service`) ذات البروتوكول المُرقّم تبقى مستقلة**؛ لا يجوز نشرها مكان خدمة الطور من دون تعديل العقود.

### اختبارات وسياسات

- أضيفت اختبارات Vitest دائمة لـ Linear Algebra وODE وواجهات التوافق القديمة، لكنها **لم تُشغّل داخل البيئة المرفوعة** لعدم وجود `node_modules`.
- أضيف `tools/audit_architecture.py` لفحص العلاقات الثابتة والاعتماد الدائري بعد أي تغيير؛ يعمل للقراءة فقط.
- أضيف `docs/architecture/BOUNDARIES.md` و`docs/architecture/VERIFICATION.md` لقواعد الحدود وخطة الاعتماد قبل الدمج.

- Python: **29/29 اختبارًا ناجحًا** على النسخة المعدلة.

- لم يتم تنفيذ `pnpm build` أو مجموعة Vitest الكاملة بسبب عدم توفر اعتمادات المشروع؛ **لا تعتمد هذه النسخة للإنتاج قبل تشغيل هذه الفحوص على Codespaces**.
